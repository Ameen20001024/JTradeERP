## Unverified or ambiguous API details

- Exact cookie attributes, CORS behavior, and refresh-token rotation are owned by the auth endpoint/configuration; verify browser-compatible secure cookie behavior in the deployment environment.
- Exact PDF/HTML print layout, content-disposition headers and TRN placement need acceptance criteria if the frontend is expected to produce fiscal invoices.
- Exact success status and content-type for every route should be runtime-captured; the endpoint source is not uniformly explicit.
- Date-only and timestamp serialization should be confirmed against representative JSON: use ISO date strings for `DateOnly` and ISO-8601 timestamps for `DateTimeOffset` only after confirming serializer behavior.
- The current code exposes several endpoint inputs as optional nullable types; whether blank query values are omitted or parsed as null is framework binding behavior and should be tested at the API boundary.
- No browser React requirements were available, so accessibility, responsive behavior, navigation, data-entry UX and screen-specific workflows remain outside this contract audit.

## Read-only safety and recommendation

No backend, migration, configuration or database changes were made during FE-00. Resolve the documentation and print-format decisions and provide the React SRS before committing FE-01 screen scope. Existing endpoints are adequate to start a thin API client and limited UI spike; they are not enough to certify complete frontend requirement coverage.
